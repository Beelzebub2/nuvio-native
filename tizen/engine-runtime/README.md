# Bounded torrent service with optional USB cache

This is a newly authored MIT loopback HTTP facade around pinned MIT `torrent-stream@1.2.1`. It contains no Stremio `server.js`, EngineFS source, proprietary runtime, or opaque upstream service blob. `build.cjs` makes explicit, fail-closed modifications of npm integrity-pinned source and produces `media-http.cjs`, `runtime-manifest.json`, and `THIRD-PARTY-LICENSES.txt`. All deployed dependencies are bundled; the TV needs no npm install or external runtime host.

Build on a development machine with Node 24 and npm 11:

```sh
npm ci
npm run build
npm test
node test-network.cjs
```

The generated service targets the Node 4.9.1 API baseline and passes a complete ES5 parser check during build. Build tools are development-only. Re-run the generated bundle and the two tests under `node:4.9.1` to verify this baseline; this is not a Samsung hardware playback certification.

Start with `require('./media-http.cjs').start({controlToken: secret, allowNullOrigin: true, proxyHandler: optionalHandler})`. The caller generates a fresh 32-byte cryptographic hex secret and transfers it only through a trusted MessagePort bridge that verifies the expected app ID. If the platform cannot supply this bridge, do not start the service. `stop(callback)` cancels all active media responses, releases the cache, destroys the engine and its peers/discovery, and closes HTTP connections. `proxyHandler(req,res)` may return true to handle a separate proxy route after common loopback/Host/Origin checks.

The service listens only on `127.0.0.1:2710`. State changes and private statistics require `X-Starlit-Token`; `Origin: null` is allowed only when configured for the signed widget. `/settings` and `/range-probe` expose fixed nonprivate data without authentication. `POST /{40hex}/create` accepts `{torrent:{infoHash},peerSearch:{sources:["dht:...","tracker:https://...","tracker:udp://..."]}}`, returns files, guessed file index and a random file-scoped playback ticket. `GET`/`HEAD /{hash}/{fileIndex}?ticket=...` supports one byte range, including suffix/open ranges; unsatisfiable/multiple ranges return 416. `POST /{hash}/remove`, `POST /removeAll`, and `GET /{hash}/stats` require the control token. `/hash/fileIndex/stats.json` aliases the stats endpoint. Media URLs contain only the per-file playback ticket. `/range-probe` contains the 22-byte ASCII string `starlit-range-probe-v1`.

There is one active torrent with up to four concurrent playback byte-range responses. AVPlay may request several non-adjacent portions of a large video simultaneously; one new range no longer cancels another. A fifth concurrent media GET is rejected with HTTP 429. After all media ranges close, incomplete piece buffers may be discarded. Protected read-only torrent statistics include an `activeRanges` count.

By default the completed-piece RAM cache is capped at 48 MiB and no torrent data is written to disk. When explicitly enabled in Samsung TV P2P settings, a trusted control-token-authenticated probe can select a writable removable drive for **temporary** disk-backed torrent pieces. USB mode has a 16 MiB RAM hot cache; disk usage is capped at 256 MiB, 512 MiB, 1 GiB or 2 GiB according to measured sustained USB write speed and free space. At least 1 GiB or 20% of drive capacity is reserved. Drives below 5 MB/s or without reliable free-space reporting are rejected; no offline or permanent downloads are created.

The app only passes a mounted external storage path obtained through Tizen's Filesystem API. The service validates the absolute directory, writes only within a dedicated `Starlit-Torrent-Cache` folder with a verified ownership marker, and removes only recognized Starlit-generated piece/probe names. Existing media and unknown files are never altered. A probe writes, flushes, reads and checks 8 MiB before enabling the cache. An unplugged or failed disk switches the active engine back to RAM and invalidates disk-only pieces for network refetch. Closing playback deletes the temporary pieces; a future probe reclaims recognized orphans left by crashes. The user must opt in through settings, and the service never assumes USB storage is present or writable.

Local endpoints `POST /cache/probe`, `POST /cache/disable`, and `GET /cache/status` require `X-Starlit-Token` from the existing trusted MessagePort handshake. Probe requests accept only a bounded JSON object containing the native root path and conservative free/total capacity. The private status response never exposes filesystem paths. Only idle streams may run a benchmark. A browser request without the control token cannot configure or write to storage.

The 48 MiB default cache and 16 MiB optional USB hot cache are **not** total process memory limits: multiple in-progress pieces, HTTP response buffers, metadata, peers and JavaScript require additional memory. Reads select one verified piece at a time per range, retrieving only the required bytes instead of reading a whole USB piece for a small HTTP request. The USB cache checks the complete on-disk file length before each partial read and falls back to RAM if the file is unavailable or truncated. RAM and USB LRU bookkeeping use constant-time linked recency lists, avoiding repeated scans as the number of cached pieces grows; no unbounded prefetch or torrent-wide memory allocation is introduced. LRU eviction invalidates the corresponding verified engine bit so it can be refetched. Metadata safety limits apply equally with and without USB: 1,024 files, 65,536 pieces, 2 MiB metadata exchange, 32 MiB maximum piece size and 1 TiB torrent size. Other bounds: 12 connections, 128 queued peers, 16 HTTP connections, eight pending identical creates and 1,024 bad-peer blacklist entries. A new torrent replaces the previous engine; removal invalidates its file-scoped playback tickets.

Peers use TCP/IPv4 and must have public addresses. UDP/HTTP/HTTPS trackers are supported; tracker DNS is checked on actual outbound connections. HTTP tracker responses are limited to 256 KiB and ten seconds, redirects to three, and repeated announce intervals to one minute through one hour. Compressed tracker responses are rejected. uTP, WebRTC/WebSocket trackers, offline downloads, and seeding uploads are disabled. The tests' `allowPrivatePeers`, `onEngine`, ephemeral `port`, and reduced cache options are programmatic synthetic-fixture hooks, never HTTP request fields or production settings.

Licenses are copied verbatim for bundled third-party code. Supplemental notices retain upstream URL provenance in `supplemental-licenses/sources.json`. The unlicensed `bitfield@0.1.0` implementation is excluded and replaced with a new MIT bitset. Small compatibility functions also replace `hat`, `flatten`, `buffer-equal`, `simple-sha1`, and the unbounded `simple-get` HTTP helper in full. The remaining legacy packages include npm advisory findings; notably `ip@1.1.5` is retained only for protocol address conversion/blocklist functionality, never for public-address security classification. Public-address security uses the separately tested native-IP/DNS policy. This legacy dependency baseline and Node 4 itself still require security review and physical Tizen validation before a production release.

`test-runtime.cjs` creates a synthetic two-file torrent in RAM, exchanges metadata and pieces over a real TCP peer, and checks exact HTTP ranges, piece-sliced reads, overlapping simultaneous ranges, bounded fifth-request rejection (429), client-abort cleanup, file boundaries, suffix/HEAD/416, demand-only loading, bounded eviction/refetch, seeks, cancellation, teardown/recreation, a delayed concurrent-create race, token/Host/Origin checks and no persistent filesystem writes in memory-only mode. `test-recency.cjs` verifies the linked LRU ordering, eviction and partial RAM reads; `test-large-metadata.cjs` and `test-limits.cjs` cover elevated metadata and piece boundaries. `test-usb-cache.cjs` checks storage sizing, ownership, cleanup, hot-cache behavior, 4 KiB reads from 32 MiB pieces, truncated-file fallback and eviction; `test-usb-service.cjs` checks token-gated USB controls. `test-network.cjs` tests public-DNS policy, tracker response caps, redirects and cancellation. These tests do not download third-party media.
